# PROJECT-BLOOM 💐 
### A bouquet across the distance.

> *"I couldn't place these flowers in your hands yet, so I made them bloom wherever you are."*

---

## Overview

Project Bloom is an interactive storytelling website built as a personal gift for someone in a long-distance relationship.

Rather than presenting a static bouquet, the experience tells a quiet story.

The night begins in silence.

A wish is spoken.

A small spark appears.

Flowers slowly grow and bloom.

Distance is acknowledged.

Love answers it.

The result is a bouquet that exists only because real flowers cannot yet cross the distance.

The experience is intended to feel timeless, intimate, and worth revisiting months or years later.

---

# Core Philosophy

Every design and technical decision should answer one question:

> **"Would this make her smile if she revisited it years from now?"**

Technical complexity is never the goal.

Emotional resonance always comes first.

Project Bloom is closer to an interactive short film than a traditional webpage.

---

# Design Principles

Nothing appears.

Everything arrives.

Flowers never pop.

They bloom.

Stems never scale.

They grow.

Leaves unfold.

Stars softly twinkle.

Sparkles briefly shine before returning to the night.

The bouquet gently breathes with the breeze.

Silence is part of the animation.

---

# Visual Direction

The atmosphere should feel:

- Dreamlike
- Romantic
- Quiet
- Organic
- Celestial
- Warm
- Timeless

Avoid:

- Neon
- Cyberpunk
- Loud gradients
- Generic Valentine's aesthetics
- Portfolio-style effects
- Flashy transitions
- Decorative excess

The moon is intentionally absent.

Because she is the moon.

---

# Flower Palette

Primary flowers:

- Tulips
- Lilies

Supporting flowers:

- Lavender
- Baby's Breath
- A small number of Roses

The bouquet should feel carefully arranged rather than randomly generated.

---

# Technical Goals

Project Bloom is designed as a static website.

Requirements:

- Vanilla HTML
- Vanilla CSS
- Vanilla JavaScript
- ES Modules
- No frameworks
- No build step
- Runs through any local HTTP server

Priority:

- Maintainability
- Compatibility
- Performance
- Readability

---

# Accessibility

Project Bloom should remain enjoyable for everyone.

Support includes:

- Keyboard navigation
- Reduced motion
- Accessible controls
- Semantic HTML
- Decorative elements hidden from screen readers
- Mobile-first interaction

---

# Performance

The experience should feel smooth on both desktop and mobile.

Focus on:

- CSS transforms
- Opacity animations
- GPU-friendly effects
- Minimal layout thrashing
- Static DOM where possible

Target:

~60 FPS on modern devices.

# Development Workflow

When implementing new features:

1. Preserve compatibility.
2. Avoid unnecessary rewrites.
3. Keep folder structure stable.
4. Prioritize emotional experience.
5. Ensure zero console errors.
6. Test desktop and mobile.
7. Maintain accessibility.
